# 私人职业工作区 · 说明与 Agent 规则

这里保存当前使用者唯一的个人资料与进展，不上传公共仓库。先读共享仓库的 Agent 规则和 setup-workspace Skill。

```text
workspace/
  AGENTS.md
  profile.md
  preferences.md
  resume/
  applications/
    index.md
```

## 资料入口与初始化

- `profile.md`：从用户简历整理的事实基准，标明来源、确认状态和缺口。
- `preferences.md`：Agent 的候选建议、用户确认的行业／岗位／地点和用户输入的薪资口径；建议与选择分开，不猜薪资。
- `resume/`：简历原件、构建源文件与生成版本；沿用用户的构建约定，不擅自覆盖或改写原件。
- `applications/index.md`：公司的路由与状态摘要，链接各公司 `log.md`；详细进展以公司日志为准。
- `applications/<公司>/log.md`：岗位、联系线、时间线、依据和下一步。公司目录在有具体个人任务时才创建。
- 公司 `materials/` 保存定制简历、未发送草稿和面试准备；`records/` 保存沟通原文、截图和附件，按需创建。

新用户提供简历后，由 Agent 整理事实、建议方向，再询问并记录行业、岗位、地点与薪资偏好。仅创建目录不表示已经完成初始化。已有工作区直接复用，未经用户要求不覆盖事实、不重复建档、不删除旧资料。语言与表达偏好也放 `preferences.md`。

## 个人进展与记录

1. 开始任务先读事实、偏好、公司索引和目标公司日志，检查历史与不再接触要求。多个联系人／岗位独立记录，一个人拒绝不代表整家公司结束。
2. 草稿、实际发送和对方回复分开；保留发生日期与记录日期，注明来源和联系人。没有依据时不能记作已投递或已回复，目录整理不计为新动作。
3. 已知公司的新记录直接保存到该公司 `records/`，核对后追加 `log.md` 并更新 `index.md` 的路由或状态摘要。不设 inbox 或 done 队列。
4. 公司或联系人归属不明时，在 `index.md` 的待核实区记录已知信息、来源和缺口，不猜主体、不凭摘要关闭联系线。跨公司原始依据确需保留时，可在 `applications/records/` 存一份并由相关日志引用；这是原始证据存放处，不是待处理队列。
5. 多 Agent 按公司分工；同一公司由一个写入者合并日志，其余补充先保存唯一原始记录，写前核对是否有并发变化。
6. 用户主动拒绝或招聘方拒绝，都先如实记入对应联系线，保留日期、结果、原因和不再接触要求；不自动移动目录。**仅在用户明确要求归档时**，才将指定公司移到 `applications/archive/`，同步索引及本地链接，保留其他联系线的实际状态与未决项。
7. 已归档的历史记录继续保留，不因为新的模板重置状态。猎头关系如有需要按实际任务维护并关联公司日志。

## 公私边界与外部动作

公开公司、渠道、人物与岗位研究直接维护共享 `data/companies/`，不要求个人初始化，不创建私人申请记录。私人简历、电话、聊天、薪酬、凭据、授权和投递状态不得复制到共享文件、模板、提交信息、Issue 或 PR。

任务只要求研究或草稿时，不发送、投递、建联或预约；实际动作依用户既有规则与明确授权范围执行，模板本身不授予权限。只在公共子仓库提交共享内容，不在私人工作区或其父目录初始化、提交或推送公开 Git。
